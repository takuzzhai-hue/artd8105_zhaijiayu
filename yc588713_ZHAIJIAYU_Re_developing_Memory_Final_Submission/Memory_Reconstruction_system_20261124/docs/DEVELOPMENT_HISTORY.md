# Latent Recall · 第 1 步

需要 Python 3.10 或更高版本。本步骤只在本地显影，不调用百炼，不需要 API key。

## 安装（macOS / Linux）

```bash
cd /Users/kk/Desktop/artd8105_zhaijiayu/latent-recall
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

百炼的 Python SDK 为 `dashscope`。依赖暂不锁版本。虚拟环境、密钥、RAW 和输出图片不提交到 Git。

## 运行

RAW 放入 `samples/`，回忆放入 `samples/memory.txt`（本步骤尚不读取回忆）。仅有一张 RAW 时：

```bash
python src/develop_test.py
```

多张 RAW 时：

```bash
python src/develop_test.py --raw "samples/_DSF9757.RAF"
```

每次在 `outputs/` 下按北京时间创建独立时间戳文件夹，保存全尺寸 16 位 PNG：

- `01_camera_default.png`：相机记录的白平衡 + rawpy 常规显影；不精确复刻相机厂商 JPEG 风格。
- `02_linear_no_camera_wb.png`：关闭自动亮度，线性伽马 `(1, 1)`，关闭相机及自动白平衡，显式使用 `[1, 1, 1, 1]` 通道增益，避免回退到日光白平衡。

第二张通常较暗、偏色，是实验显影，仍经过解码、去马赛克与色彩转换，并非传感器原始数据。线性像素直接供普通查看器显示，未嵌入线性色彩配置，不用于标准色彩交付。

目录：`src/` 代码，`samples/` 素材，`outputs/` 结果，`prompts/` 后续提示词。

参考：[rawpy 参数](https://letmaik.github.io/rawpy/api/rawpy.Params.html)、[百炼 SDK](https://www.alibabacloud.com/help/en/model-studio/install-sdk)。

本机 Python 曾出现证书验证错误，安装时可使用系统证书：

```bash
python -m pip install --cert /etc/ssl/cert.pem -r requirements.txt
```

## 第 2 步：操作表和语义分析提案

`src/operations.py` 定义操作名称、global/local 范围、参数、解释、记忆例句和处理阶段。所有效果目前是定义，尚未实现第 3 步的引擎。`planned` 可提出参数方案，`experimental` 需验证，`deferred` 暂不接入。

全局并不等于 RAW 参数：曝光、白平衡等走 rawpy；饱和度、对比度、模糊等走后处理。后处理应明确线性 RGB 与显示 RGB 的转换，使用浮点数据，最后才量化导出。目录中的实现描述是后续引擎的约定，不表示本步骤已经应用这些效果。

新增 `local_glow` 对应手发光；`noise_emphasis` 区分保留噪声与放大高频；`color_shift.degrees` 为 -180 到 +180 度，方向未明确时需确认。生成、已有色差保留/主动错位、多帧/单帧拖影分别记录。位置不明确的 void 先记 missing 和旁注，不创建假蒙版。

导出操作表到终端：

```bash
python src/operations.py
```

API 分析：复制 `.env.example` 为 `.env`，在本机编辑 `DASHSCOPE_API_KEY`，区域与接口须匹配。输入是语音转写后的文字，当前不包含录音和语音识别。不会上传 RAW。此步骤只生成语义提案，不执行图像处理。

```bash
cp .env.example .env
# 编辑 .env 填入密钥，并把文字写入 samples/memory.txt
python src/analyze_memory.py --text-file samples/memory.txt --regions "他的手" "背景"
```

区域名应来自实际已建立的区域；此入口只检查名称，后续引擎还需检查蒙版文件。结果保存到时间戳目录的 `analysis.json`。结构/范围验证失败重试一次；temperature=0 仍不能保证服务端每次输出一致。当前使用本地字段与范围校验，第 5 步可进一步统一 JSON Schema。无 API key 时明确报错，不以本地规则冒充 API 分析。

## 照片 + 文字流程（新增）

使用 `photo_pipeline.py` 运行“照片 → 视觉观察 → 结合文字拆意图 → 修改预览”。支持 RAW 和 Pillow 支持的常见图片。RAW 先本地常规显影，预览统一缩至最长边 1600 像素并移除元数据，发送给百炼视觉模型；原始 RAW 不上传。接着把视觉观察与用户文字交给文本模型。视觉模型默认 `qwen3-vl-plus`，可用 `.env` 中 `DASHSCOPE_VISION_MODEL` 改动，原有文字模型保持不变。

```bash
python src/photo_pipeline.py --photo samples/_DSF9757.RAF --text "我感觉这张照片的对比应该更强烈一点，变得更加复古一点，这个钟摆会移动一些，是一种时间流过的感觉。"
```

输出独立文件夹，包含原始预览、视觉观察 JSON、意图和执行日志、步骤图与结果预览。当前实际支持：对比度、饱和度、全局模糊、抬黑、暗角、像素化、色相偏移。其他效果不假装执行；缺少局部蒙版、含糊风格和未接入操作会明确记录。视觉识别不等于像素级蒙版，也不保证识别正确。

这里的图像处理只作用于最长边 1600 像素的 8 位显示预览，以验证整体流程。第 3 步仍需实现完整 RAW 重显影引擎。当前还没有上传网页，命令中的 `--photo` 对应用户提供照片的入口。API 会接收该照片的缩小预览和输入文字。

### 主动诠释更新

用户已授权模型根据画面主动衍生视觉效果：复古不再默认要求确认，可以组合冷暖、褪色、暗角等；钟摆运动可自动定位后应用方向模糊。视觉 API 结合用户文字返回归一化区域框，程序生成羽化矩形蒙版并保存。自动框不等于语义分割，可能包含背景；查看结果时应一并检查蒙版。识别不可靠时仍记录缺失，不编造对象。

预览处理器现在另外支持曝光、冷暖、局部提亮/模糊/锐化/辉光、运动模糊。预览的曝光和冷暖是对 RGB 的近似处理，最终 RAW 引擎仍需使用 rawpy 参数重新显影。模型可衍生组合，不受例句绑定；真正新增的效果算法仍需实现，不会把模型随意编出的操作名执行为代码。

## 第 3 步：叠加式显影引擎（按最新确认）

`src/engine.py` 接受 RAW 与手写操作 JSON，不调用 API，没有随机处理。RAW **只在开始显影一次**，每一步在上一结果上继续处理；以前的局部操作不会重新应用。默认 `half_size=True`，输入内存使用浮点图像，输出 16 位 PNG。此模式会累积模糊、裁剪和色彩变化，反向操作不保证复原。

```bash
python src/engine.py --raw samples/_DSF9757.RAF --operations examples/operations.json
# 全尺寸输出（大 RAW 会使用更多内存和时间）
python src/engine.py --raw samples/_DSF9757.RAF --operations examples/operations.json --full-size
```

输出 `outputs/engine_时间戳/step_00.png` 为起点，`step_01.png` 等对应每个输入操作。`log.json` 保存原句、名称、参数、区域、成功/无法执行/与之前的操作冲突、原因、历史操作、源文件与图像校验值、依赖版本。无法执行或冲突步骤不改变图像，但仍保存对应图片；显影或保存文件失败则停止并报错。`--output` 可指定新目录，拒绝覆盖已有目录。

JSON 可直接为操作数组（仅全局操作），也可为 `{"regions":{"钟摆":"pendulum_mask.png"},"operations":[...]}`。每项包含 `source`、`name`、`parameters`、`region`。蒙版路径相对 JSON 文件目录，必须为对应**方向正确的完整图像**的 8/16 位灰度图；白色为作用区，黑色不处理，灰色渐变混合。比例匹配时自动缩放至半尺寸或全尺寸。

示例蒙版手工采用此前钟摆位置框，是近似区域，仅适用现有 `_DSF9757.RAF`。示例包含对比、局部运动、褪色、空白处理，以及故意设计的冲突和参数越界，用于检查三种日志状态。

叠加模式下曝光在图像线性化后乘增益，冷暖在 RGB 上近似调整，不修改 rawpy 显影参数或重新取回 RAW 细节。初始显影关闭自动亮度，用相机白平衡。支持预览处理器已有操作和 void；传感器实验、生成等仍明确记为无法执行。void 后继续要求处理该已抹除区域记冲突并跳过；普通先暖后冷或先亮后暗允许作为连续创作记录，不自动当作矛盾。

同一 RAW、JSON、蒙版、尺寸选项及相同依赖/平台应生成相同图像；时间戳目录不同，不保证跨软件版本和硬件逐字节一致。此引擎独立于此前网页预览流程，本步骤尚未替换网页的 1600 像素处理器。

## 第 4 步：自动物体轮廓分割

当前流程已改为：百炼结合回忆定位对象 → 本地 SAM 2.1 Tiny 按位置提示提取轮廓 → 轻微羽化蒙版 → 局部叠加处理。网页默认自动执行，不需要手动画区域。绿色覆盖图展示修改范围，结果包保存二值蒙版、羽化蒙版、覆盖图、模型版本和分割评分。

初次安装需要下载本地模型；此模型无需额外 API key：

```bash
python -m pip install -r requirements.txt
python src/segmentation.py --download
python src/app.py
```

模型缓存位于 `.models/`，不提交 Git；正常生成从本地读取，不自动联网下载。分割失败、评分偏低、空蒙版或位置明显不符时不回退为矩形，也不修改该局部；仍允许全局效果。质量检查是启发式规则，不保证语义正确，细线、遮挡和多个相似对象仍需查看覆盖图。

每轮生成额外保存 `engine_operations.json`，其中包含已分割蒙版路径及文字操作，可交给第 3 步引擎：

```bash
python src/engine.py --raw samples/_DSF9757.RAF --operations outputs/你的运行目录/engine_operations.json
```

如该轮没有任何操作提案，引擎会报告空列表，不执行。每轮语义理解和图像处理仍独立进行；三次生成与条带拼合功能保持可用。

依据：[SAM 2 模型接口](https://huggingface.co/docs/transformers/model_doc/sam2)、[Meta 官方 Tiny 模型](https://huggingface.co/facebook/sam2.1-hiera-tiny)。这是文字引导定位加提示式物体分割，不是仅靠 SAM 理解文字。

## 2026-11-11 当前交互与风格规则（覆盖此前次数、条宽设置）

用户只上传照片和输入回忆。第一轮图像/文字分析后，按独立意图数自动选择生成数量：1–2 个意图为 3 张，3–4 个为 5 张，5 个及以上为 6 张。不再显示张数、方向、像素宽度选项。

使用原图横向尺寸 W 作为最终拼合画布宽度，分为 N+1 段，边界为 floor(i*W/(N+1))。最左段取原图对应位置，后续段依次取第 1 到 N 张结果对应位置；整数余数最多相差 1 像素，不循环取条、不挤压整张照片。独立处理结果仍是最长边 1600 像素的预览，拼合放大到源图尺寸不会恢复额外细节。

网页调用 `style.py` 约束轻微摄影风格：冷暖最多 ±0.06，对比/饱和度最多 ±0.12，抬黑最多 0.08，暗角最多 0.12；同一区域同类操作不重复叠加。日志同时保存原始模型提案和实际执行参数。轻微整体/局部失焦、运动模糊可被主动诠释。

分割不包含固定钟摆假设，依据当次照片和用户文字。视觉模型可标注 selection=highlights；SAM 先提取物体区域，再按该区域亮度第65百分位选取亮部。这是亮部的明确可追踪阈值规则，不声称模型能保证任何材质都识别正确。

### 当前强度：略微明显但克制

冷暖上限从±0.06调至±0.10，饱和度/对比度从±0.12调至±0.18，曝光从±0.3调至±0.45档；局部提亮最多0.5档。模糊、暗角等小幅提高。模型建议幅度与执行上限同步更新；仍保留去重、原图判断和参数日志。仅影响后续生成，已有结果不修改。

## 当前主流程更正：单次分析、顺序累计

覆盖此前“3/5/6 次独立生成”的规则。网页只调用一次完整分析流程，每个操作都在上一步结果上继续处理。顶层 result_01、result_02 等逐个复制同一个 run_01 中成功的 step 图片，不再取多轮的最终图。成功步骤数即结果张数，不凑固定数量；原图加这些阶段图按对应位置等宽拼合。series.json 记录每张结果对应的 source_step、操作、原句与前一步。

### 实时展示阶段图

网页每完成一个操作即追加一张阶段图；看图、分割、制定计划阶段分别显示状态。全部步骤结束后才拼合和打包。处理分辨率保持最长边1600像素。若中途失败，已展示和已保存的阶段图保留。

### 局部目标自动自查

出图前若存在分割失败或 missing 意图，自动把原因反馈给视觉模型，再定位、分割和规划一次。有效旧蒙版保留，不重复执行图像操作；仍无法定位时明确记录，不把失败改成成功。实体用 SAM 轮廓，树影等光影可使用模型定位范围内的亮度蒙版；shadows 选择区域内较暗部分，highlights 选择较亮部分。日志记录 method 和阈值，不冒称亮度蒙版为物体语义分割。多棵树分别定位，避免以整图框作为单个树干。

### 最少三张与本地兜底

正常可读取图片：先让模型推测口语/隐喻并匹配摄影操作，按现有规则重试格式及区域定位；API 拒绝、网络或格式异常、操作失败、成功阶段不足三张时，保留已有阶段并追加本地明暗调整。每步默认约±0.2EV，方向由当前平均亮度决定，一组兜底曝光累计不超过1EV；曝光不能改变纯黑等极端输入时使用小幅像素亮度偏移。每张必须与上一张像素不同。原先未实现的语义保留在日志，兜底标 fallback=true，不冒称完成局部效果。

兜底发生在已有成功阶段之后，也逐张返回网页，最后统一拼合。照片损坏无法解码、磁盘写满、进程被终止等基础设施错误无法承诺出图；提示用户处理输入或环境问题，不伪造成功。当前仍为1600像素处理。\n

## 摄影媒介变化（2026-11-12）

版本一备份不变，以下只加入当前开发项目。保留最长边1600预览、逐步累计、每一步刷新、最后条带拼合的流程。

- 隐藏整张照片：逐渐白化到纯白；隐藏某人：分割后只白化人物轮廓。
- “照片原本的样子”“不想看到这张照片”：作者约定的粗大合成颗粒隐喻，不是RAW采样数据还原。
- 破损、脱落、断掉：像素排序、乳剂剥落模拟、块状数据损坏模拟。
- 主体或脸记不清：分割目标，模糊并向柔白扩散。
- 焦点换到某物体：分割新目标，保留该区域当前已有细节，虚化其余区域。无法恢复前序步骤已经破坏或原本失焦的细节。
- 其他新增：欠曝沉没、边缘漏光、曝光不均、负片、倾斜清晰带、重影、边缘像差、长曝光轨迹、狭缝拉伸、快门拖影、通道褪色、印相痕迹。
- 像场显露仅模拟原画幅内的圆形边界，不生成画外信息，也不扩展实际取景范围。

操作表与执行模块分别位于 src/operations.py、src/media_effects.py；语义规则位于 prompts/translator.txt。全局效果可选local_版本（image_circle除外），焦点与曝光保留区域使用focus_pull、uneven_exposure。后两者保留蒙版内，改变蒙版外。
普通调色仍采用原强度限制；媒介操作可明显变化。少于三项操作且包含媒介效果时，将其中一项拆成渐进强度的累计阶段，避免完成纯白后再用曝光补足张数。失败处理沿用现有重试和明暗兜底，日志保留真实原因。

合成颗粒采用固定坐标哈希，不使用随机状态。媒介效果在执行记录中标记 simulated=true，并保留语义解释 interpretation。所有效果是艺术模拟，不代表真实材料损伤、实际运动轨迹或历史事实。18项本地测试通过；百炼验证了白化、粗颗粒、焦点迁移、主体柔白四种语义，并完成一张既有照片的视觉理解→像素排序→三阶段输出。分割仍需结合每张实际照片检查，不能保证任何对象都正确识别。

## 缺失对象的局部生成补充（2026-11-12）

仅当用户原话明确提及需要补入的具体对象，且看图确认当前缺失时，才允许 generate_add。普通调色、模糊、隐藏、否定添加、纯比喻和分割失败不触发。对象名和引文必须逐字来自输入；原话中的“我记得/好像本来还有”允许作为作品的推测性补入意图。定位由视觉模型提出，面积不超过画幅30%，不使用SAM去分割一个不存在的对象。图像编辑使用局部裁片作为底图、整张照片作为光线和风格参考；小裁片放大到接口建议的输入尺寸，输出后缩回原位置，仅合成许可范围。

处理顺序：缺失对象计划→语义操作列表→执行到该步时再次检查原话和当前图→生成一个候选→只合成允许区域→AI检查最终合成图。只有通过的结果进入累计序列；前后继续原有摄影效果，不为凑张数重复生图。审核不通过或请求失败时，在同一张上一步图片上重试一次（新种子、反馈修正），最多两次。两次失败保留原图，写明原因，网页仍按既有机制补足基础明暗阶段，不把基础调整冒充生成成功。

生图匹配原照片夜景/日景、光线、颗粒、透视、景深；禁止自行添加装饰。服装和道具用通用朴素款式，手保持中性自然。新增脸部走本地无五官白色脸形+高斯模糊，不调用真实人脸生成；新增人物也要求白色模糊脸，并在审核中检查。已存在但模糊的脸仍使用摄影效果，不生成身份。

使用现有DASHSCOPE_API_KEY，图像模型默认qwen-image-2.0-pro，可通过DASHSCOPE_IMAGE_MODEL修改；接口默认依据DASHSCOPE_BASE_URL地域推导，也可设置DASHSCOPE_IMAGE_ENDPOINT为完整原生编辑接口。需账号拥有该模型权限及额度。图像模型prompt_extend=False、n=1；保存种子、裁片坐标和提示词，但云模型不保证像素级复现。审核同时查看整图对比与区域放大对比，只判断当前新增步骤，不把后续尚未执行的调色当成失败。
官方接口依据：https://help.aliyun.com/zh/model-studio/qwen-image-edit-api

新增文件：src/generation.py、prompts/addition_planner.txt、addition_edit.txt、addition_review.txt。缺失意图记录addition_plan.json；每次生成目录保存gate.json、allowed_mask.png、region_generated_overlay.png、generation.json和通过的accepted.png。generation.json包含提示词、种子、模型、审核及失败原因，不保存密钥、临时图片URL和未通过候选图。阶段及后续累计图片在网页标注“含AI补充”，series.json保留生成内容来源；标记不烙印进照片。生成允许范围之外的像素严格保持上一步结果。AI的对象识别和美观判断仍可能误判，需要用户检查最终效果。

独立命令行RAW引擎不执行generate_add；该操作依赖网页流程的缺失计划与审核。版本一备份不包含这些新功能，保持不变。

生成后还会定位并分割新增物品，合成物品轮廓及少量接触阴影，避免复制整块生成背景。自查在实际合成后执行，失败候选不作为正式阶段或下载图片。物品分割失败也会触发本轮重试；第二次仍失败则保持上一张结果。

合成前以物品周围同位置背景估计原图与生成裁片的曝光差，做有界局部亮度校正，避免夜景里物品无故发亮；不会改变允许区域外的原片。审核通过后另存applied_mask.png记录实际改变的像素。

本轮验证：29项自动检查通过。真实百炼调用验证普通复古、隐藏照片、否定添加均不产生新增计划；真实海边照片的小贝壳补入完成定位→生成→物品分割→局部光线匹配→合成→自查，第一候选被拒绝、第二候选通过。其余具体物品和人脸轮廓仍需结合实际照片检查，不能把自查通过视为绝对正确。

### 镜头前的食指与手势
拍摄回忆提及食指、指向/触摸建筑时，默认镜头前的近景手势，除非明确说明是远处人的手。计划需返回tip指尖目标和entry_edge入画边，程序将生成范围延伸到对应画布边缘；不使用飞鸟或接触点的小框代替整段手势。保留必要掌根、腕部与自然收拢的其他手指，手允许中性真实皮肤，白色无五官规则仅用于脸。贴着照片边缘的手腕不再因边界羽化而淡出。规划范围不合格会重新看图一次；网页完成状态会直接展示新增失败原因。

近景手使用完整照片构图生成，单独通过addition_hand.txt约束食指与天际线对齐。分割保留自然连接的整只手而非仅食指；允许小幅超出规划位置框来保留完整指尖，要求至少75%的轮廓仍在规划区且实际轮廓不超过画幅30%。偏离过大重试，不裁断手指。手不向远处背景投接触阴影，轮廓仅小幅柔化。

## 双页摄影界面

启动方式仍为 `python src/app.py`，访问 http://127.0.0.1:7860 。新界面使用 FastAPI + 原生 HTML/CSS/JavaScript，继续调用原有 `series.generate_series` 真实后台，没有示意生成或假进度。原 Gradio 页面留在 `src/gradio_app.py`，需要时可单独启动（先关闭占用同一端口的新网页）。

输入页支持点击与拖放、同区域等比例预览、更换照片、多行回忆；有效照片和文字齐备才可开始。生成页使用约2秒淡入、阶段编号回看、最后出现的拼合图与ZIP下载。动画遵循系统“减少动态效果”设置。张数未确定时显示“—”；后续展示计划张数，完成后以实际张数为准。基础调整与未完成请求有简短说明，详细原因可展开。界面组件不使用装饰性颜色，照片保留自己的色彩。

`web/api.js` 为前后端适配层。后台作业在单独线程排队运行，轮询获取真实进度，关掉页面不会取消正在执行的任务。同一浏览器会话最多一个活动任务；刷新后可恢复当前服务进程中的任务。上传与结果按浏览器会话隔离，文件类型和内容均需验证，单文件上限512MB。临时上传及预览位于outputs/web_uploads；关闭并重启服务后内存任务入口失效，但outputs中的结果文件保留。本地单进程使用，不是公网多租户部署配置。

ZIP现在包含原始上传文件 `original_upload.<原扩展名>`（RAW也保留原文件）、显影原图、每张result阶段图、composite.png、原样保存的memory.txt及已有处理记录。不会包含API密钥。

### 成像管线实验（2026-11-21）

新增操作：`sensor_sites`、`faded_fog`、`raw_wb_split`、`raw_demosaic_linear`、`raw_half_detail`、`raw_noise_gain`、`raw_camera_color`、`linear_negative`、`local_linear_negative`、`local_exposure_erase`、`dual_development`、`multi_frame_median`。四周变暗沿用 `vignette`。

网页仍按上一结果累计。真实 RAW 效果读取同一源文件的常规显影与实验显影，将差值合入当前图像；因此实际日志标为 **R+E**，并记录合成方式。采样显示读取 `raw_image_visible` 和 `raw_colors_visible`，依实际 CFA 和方向构建，不把富士 X-Trans 假装成 Bayer。缩小显示按 CFA 周期抽取完整块，格点是可视化，不是完整传感器的逐像素等尺寸输出。JPEG/HEIC 不执行这些 RAW 专属操作。

雾感使用显示端黑白位压缩，属 E：`user_black` 调高并不等于抬黑发灰。线性负像和局部曝光消隐也属 E；后期输出裁剪不改变拍摄时传感器的饱和状态。原生通道显示为伪色实验，不是准确 sRGB 转换。LINEAR 仍然插值，不保证出现伪色。half_size 在小预览上可能不明显；无变化会如实记录。rawpy 默认不做镜头暗角校正，不能假称“关闭暗角补偿”产生了变化。

多帧中值仅在命令行引擎接入：JSON `multi_frame_median` 的 `parameters.frames` 给出至少两个额外 RAW 路径（相对于 JSON 文件），加上 `--raw` 指定的主图共至少三帧。来源需同场景同画幅，先对齐再逐像素中值；始终停留的人不保证消失，配准失败拒绝合成。网页单张上传时明确标记此项需要多帧，不生成虚构背景。示例操作：

```json
{"source":"那时街上好像没人","name":"multi_frame_median","parameters":{"frames":["frame_02.dng","frame_03.dng"]},"region":null}
```

语义支持中文、英文及混合输入。作品引用仅作为用户提供的视觉参照保存在操作目录中，不代表已核实原作创作方法或复现原作参数。禁止整张全白/全黑的规则继续有效。

### 非生成注意力、剪影与触觉（2026-11-21）

`depth_focus` 用本地 Depth Anything V2 Small 估计相对深度，以成功分割的目标深度为焦点逐级合成虚化，保留目标已有细节；保存相对深度数组和预览。它不是物理深度或光学重新对焦。模型缺失/推理失败时明确记为“蒙版合成虚化”降级。官方权重固定 revision `5426e4f0f36572d16453bbda7a8389317b1bef99`，与SAM共用 `.models/` 缓存；模型不会随ZIP输出。

`local_silhouette` 沿SAM人物蒙版填黑、灰或白，分割外的照片不变。拒绝几乎覆盖全图的蒙版。不生成新人物或五官。

`touch_trace` 沿实际目标区域作定向擦抹并绘制确定性的抽象指纹脊线，不读取真实指纹，不调用生成模型。默认 smudge 为 E；exposure 模式以痕迹蒙版驱动 RAW 显影差异，确实读取 RAW 时记 R+E，普通照片上只记 E。只提到痕迹不会触发生成手。
